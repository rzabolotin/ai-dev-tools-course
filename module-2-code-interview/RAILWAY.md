# Railway Deployment Guide

Quick guide for deploying to [Railway](https://railway.app).

## Prerequisites

- GitHub account with this repository
- Railway account (free tier available)

## Step-by-Step Deployment

### 1. Create MySQL Database

1. Go to [Railway Dashboard](https://railway.app/dashboard)
2. Click **New Project** → **Deploy MySQL**
3. Wait for deployment to complete
4. Click on MySQL service → **Variables** tab
5. Copy the `MYSQL_URL` value (looks like: `mysql://root:password@containers-us-west-xxx.railway.app:3306/railway`)

### 2. Deploy Application

1. In the same Railway project, click **New Service** → **GitHub Repo**
2. Connect your GitHub account if not already connected
3. Select this repository (`module-2-code-interview`)
4. Railway will auto-detect `Dockerfile.prod`

### 3. Configure Environment Variables

1. Click on your app service → **Variables** tab
2. Add variable:
   - **Name:** `DATABASE_URL`
   - **Value:** Your MySQL URL from step 1, but change prefix:
     ```
     mysql+aiomysql://root:password@containers-us-west-xxx.railway.app:3306/railway
     ```
     (Replace `mysql://` with `mysql+aiomysql://`)

### 4. Configure Build Settings

1. Go to **Settings** tab
2. Under **Build**:
   - **Dockerfile Path:** `Dockerfile.prod` (should be auto-detected)
   - **Docker Build Context:** `.`
3. Under **Deploy**:
   - **Custom Start Command:** Leave empty (uses CMD from Dockerfile)

### 5. Deploy

1. Click **Deploy** button
2. Watch logs in **Deployments** tab
3. Wait for build to complete (~3-5 minutes first time)

### 6. Get Your URL

1. Go to **Settings** tab
2. Under **Networking**, click **Generate Domain**
3. Your app will be available at: `https://your-app-name.up.railway.app`

## Verify Deployment

Test your deployment:

```bash
# Health check
curl https://your-app-name.up.railway.app/health

# Create session
curl -X POST https://your-app-name.up.railway.app/api/sessions \
  -H "Content-Type: application/json" \
  -d '{"language":"javascript","code":"console.log(\"Hello Railway!\")"}'
```

Open browser: `https://your-app-name.up.railway.app`

## Troubleshooting

### Build Fails

**Check logs:**
- Go to **Deployments** → Click on failed deployment → View logs

**Common issues:**
- Missing `Dockerfile.prod` → Ensure it's in repository root
- Build timeout → Increase build timeout in Settings → Deploy → Build Timeout

### Database Connection Errors

**Error:** `Can't connect to MySQL server`

**Solutions:**
1. Verify `DATABASE_URL` format: `mysql+aiomysql://...` (not just `mysql://`)
2. Check both services are in the same project (shared private network)
3. Database must be fully deployed before app starts

**Fix:**
- Update environment variable with correct format
- Trigger new deployment: **Deployments** → **Redeploy**

### App Starts But Shows 404

**Issue:** Static files not serving

**Check:**
1. Deployment logs show: `INFO: Uvicorn running on http://0.0.0.0:8000`
2. No errors about missing `static` directory

**Debug:**
```bash
# Railway CLI (install: npm i -g @railway/cli)
railway login
railway link
railway run bash

# Inside container
ls static  # Should show index.html, assets/, etc.
```

### WebSocket Connection Fails

Railway automatically handles WebSocket upgrades. If it fails:

1. Check browser console for errors
2. Verify WebSocket URL is `wss://` (not `ws://`) in production
3. Our `config.ts` auto-detects this, so should work automatically

## Custom Domain

1. **Settings** → **Networking** → **Custom Domain**
2. Add your domain: `yourdomain.com`
3. Add DNS records (Railway provides instructions):
   ```
   CNAME @ your-app-name.up.railway.app
   ```
4. SSL certificate auto-generated by Railway

## Backup Database

```bash
# Install Railway CLI
npm i -g @railway/cli

# Login
railway login

# Link to project
railway link

# Backup
railway run mysqldump -h containers-us-west-xxx.railway.app \
  -u root -p railway > backup.sql

# Enter password when prompted
```

## Rollback

1. **Deployments** tab
2. Find previous successful deployment
3. Click **...** → **Redeploy**

## Environment-Specific Configs

To use different configs for staging/production:

1. Create separate Railway projects (e.g., "code-interview-prod", "code-interview-staging")
2. Each can connect to different database
3. Deploy from different branches:
   - Production: `main` branch
   - Staging: `staging` branch

Configure in Settings → Deploy → Branch: `staging`
